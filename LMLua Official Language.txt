1. Introduction
LMLua is a programming language that fuses the clean, minimal syntax of Lua with the function classification system of C++. It is designed for game and server development where code needs to be explicitly divided into server-side, client-side, and shared logic, and where common game primitives (vectors, dimensions, instances) are first-class citizens.

LMLua is the scripting language of LiMe, a Roblox-style game engine. Every script embedded in a .lw file is LMLua source.

1.1 Design Goals
Lua-first syntax — anyone who knows Lua can read LMLua in minutes.

Explicit function roles — server, client, and func clearly mark where code runs.

Explicit mutability and scope — var, const, global, and cglobal unambiguously declare intent.

Game-oriented primitives — Vec2, Vec3, Dim, and Inst are built into the language.

Zero-cost abstraction — LMLua transpiles to plain Lua; qualifiers add no runtime overhead.

1.2 Hello, World
| output("Hello, World!")

Compiles to:

| print("Hello, World!")

2. Lexical Structure
2.1 Comments
Identical to Lua. Single-line comments begin with --. Multi-line comments are wrapped between --[[ and ]].

2.2 Identifiers
An identifier begins with a letter or underscore, followed by letters, digits, or underscores. Examples: name, _private, player1, MAX_HP.

Identifiers are case-sensitive.

2.3 Keywords
and, break, cglobal, client, const, do, else, elseif, end, false, for, func, function, global, if, in, nil, not, or, repeat, return, server, then, true, until, var, while.

2.4 Literals
Number: 42, 3.14, 0xFF, 1e-5

String: "hello", 'world', long strings via [[...]]

Boolean: true, false

Nil: nil

Table: { 1, 2, 3 } or { x = 1, y = 2 }

2.5 Statement Termination
Statements are terminated by newlines or whitespace, not semicolons. Semicolons are optional and ignored.

3. Variables & Constants
LMLua has four kinds of variable bindings, spanning both scope (local vs. global) and mutability (mutable vs. immutable).

3.1 var — Mutable Local
Declares a mutable local variable. Scoped to the current block.

| var hp = 100
| var name = "Knight"
| var items = {}

Reassignment is allowed. Compiles to local hp = 100.

3.2 const — Immutable Local
Declares an immutable local. Any attempt to reassign triggers a compile-time error.

| const MAX_HP = 999
| const PI = 3.14159

Writing MAX_HP = 500 afterwards produces a compile error: cannot assign to const 'MAX_HP'. Compiles to local MAX_HP = 999.

const is shallow — table fields remain mutable.

3.3 global — Mutable Global
Declares a mutable global. Visible across all scopes.

| global score = 0
| global playerList = {}

Reassignment is allowed anywhere. Compiles to score = 0 with no local prefix.

3.4 cglobal — Immutable Global
Declares an immutable global. Visible across all scopes, but cannot be reassigned anywhere in the program.

| cglobal VERSION = "1.2.0"
| cglobal GRAVITY = 9.81
| cglobal TICK_RATE = 60

Writing VERSION = "2.0.0" anywhere produces a compile error: cannot assign to cglobal 'VERSION'. Compiles to VERSION = "1.2.0" with a program-wide compile-time guard.

3.5 Declaration Summary
Keyword	Scope	Mutable
var	Block-local	Yes
const	Block-local	No
global	Program-wide	Yes
cglobal	Program-wide	No
4. Functions
4.1 server function — Server-Side
Marks a function as executing on the server. In a networked game, this is where authoritative logic lives.

| server function player:heal(amount)
| ...
| end

Compiles to function player:heal(amount) ... end.

4.2 client function — Client-Side
Marks a function as executing on the client. Used for UI, input, and rendering.

| client function drawHud()
| ...
| end

Compiles to function drawHud() ... end.

4.3 func — Shared / Neutral
A plain function, callable from either side. Equivalent to Lua's default function.

| func add(a, b)
| return a + b
| end

Compiles to function add(a, b) return a + b end.

4.4 Method Syntax
The colon (:) syntax works exactly as in Lua. server function Player:damage(amount) is sugar for server function Player.damage(self, amount).

4.5 Anonymous Functions
LMLua does not support anonymous functions or lambdas. Every function must be named via one of the three qualifiers. If you need to pass a function as an argument, define it with func first, then pass its name.

4.6 Return Values
Return semantics are identical to Lua — multiple return values are supported.

5. Operators
5.1 Arithmetic
+ addition, - subtraction, * multiplication, / division, % modulo, ^ exponentiation, -x unary negation.

5.2 Comparison
== equal, ~= not equal, < less than, > greater than, <= less or equal, >= greater or equal.

5.3 Logical
and logical AND, or logical OR, not logical NOT.

5.4 Concatenation and Length
.. concatenates strings, # returns the length of a string or table.

5.5 Precedence (highest to lowest)
Exponentiation, then unary operators (not, #, -), then multiplication/division/modulo, then addition/subtraction, then concatenation, then comparison, then and, then or.

6. Control Flow
Control flow is identical to Lua.

6.1 if / elseif / else
| if <condition> then
| ...
| elseif <condition> then
| ...
| else
| ...
| end

6.2 while
| while <condition> do
| ...
| end

6.3 repeat / until
| repeat
| ...
| until <condition>

6.4 Numeric for
| for i = 1, 10 do
| ...
| end

An optional third value provides the step: for i = 10, 1, -1 do ... end.

6.5 Generic for
| for k, v in pairs(tbl) do
| ...
| end

6.6 do Blocks
Standalone do ... end blocks introduce a new lexical scope.

6.7 break and return
Both work identically to Lua.

7. Tables
Tables are identical to Lua. You can construct empty tables, arrays, maps, and mixed tables. You access fields with dot notation or bracket notation. You mutate fields by assignment. You get length with #. You iterate with pairs and ipairs.

8. Output & I/O
8.1 output
LMLua renames Lua's print to output. Calling output("Hello") compiles to print("Hello").

8.2 Standard Library
All other Lua standard library functions are available under their normal names:

math — math.floor, math.min, math.max, math.random, etc.

string — string.format, string.sub, string.find, etc.

table — table.insert, table.remove, table.sort, etc.

io — io.open, io.read, io.write, etc.

os — os.time, os.date, os.clock, etc.

coroutine — coroutine.create, coroutine.resume, etc.

In a sandboxed LMLua environment, io and os may be restricted.

9. Scoping Rules
LMLua uses lexical scoping, identical to Lua.

var and const bindings are scoped to the innermost enclosing block — whether that is an if, for, while, do, or function body.

Function parameters and locals are scoped to the function body.

global and cglobal bindings are visible everywhere, including inside functions.

A const binding may not be reassigned within any inner block where it is still in scope. A cglobal binding may not be reassigned anywhere in the program.

10. Error Handling
Error handling is inherited from Lua.

The error function raises an error, and assert raises one if a condition is false. The pcall and xpcall functions catch errors.

Because anonymous functions are forbidden, callbacks for pcall must be named functions defined with func.

10.1 Signal Errors
Calling :FireServer, :FireClient, :FireClients, or :Fire with wrong argument counts raises an error at the call site. Connecting a signal with a non-function argument raises an error at :Connect.

10.2 Instance Errors
Inst.new raises an error if the class name is invalid:

| Inst.new: "Plank" is not a registered instance class

Accessing a nonexistent instance via game:find() raises an error. Direct dotted access (workspace.Floor) returns nil if the instance doesn't exist.

11. Built-in Types
LMLua ships with four built-in constructors for common game primitives.

11.1 Vec3 — 3-Dimensional Vector
A Vec3 represents a point or direction in 3D space with x, y, and z components.

Constructor: Vec3.new(x, y, z)

Fields: x, y, z — all numbers

Common operations: :magnitude(), :normalize(), :dot(other), :cross(other), :lerp(other, t)

Supports +, -, and * via metatables

| var position = Vec3.new(10, 5, -3)
| var normal = Vec3.new(0, 1, 0)
| var distance = position:dot(normal)

11.2 Vec2 — 2-Dimensional Vector
A Vec2 represents a point or direction in 2D space.

Constructor: Vec2.new(x, z)

Fields: x, z — both numbers

Common operations: :magnitude(), :normalize(), :dot(other), :lerp(other, t)

Supports +, -, and * via metatables

The second argument is named z (not y) so that Vec2 shares a consistent coordinate convention with Vec3's ground plane.

11.3 Dim — Dimensions (Width × Height)
A Dim represents the size of a 2D surface — a UI element, window, sprite, or viewport.

Constructor: Dim.New(w, h)

Fields: w (width) and h (height) — both numbers

Common operations: :area() returns w * h, :aspectRatio() returns w / h

Note the capital N in Dim.New, unlike Vec2.new, Vec3.new, and Inst.new which use lowercase new. This matches the original specification.

11.4 Inst — Runtime Instance
Inst is the base constructor for runtime instances — objects that exist in the game world, UI tree, or scene graph.

Constructor: Inst.new(instID, parent?, name?, properties?)

See Section 12 for full details.

11.5 Type Summary
Type	Constructor	Fields	Purpose
Vec3	Vec3.new(x, y, z)	x, y, z	3D position or direction
Vec2	Vec2.new(x, z)	x, z	2D position or direction
Dim	Dim.New(w, h)	w, h	Width × height size
Inst	Inst.new(instID, ...)	see Section 13	Runtime instance
12. Instance Creation
12.1 Inst.new(...)
The Inst type is the base constructor for runtime instances.

Signature:

| Inst.new(instID, parent?, name?, properties?)

Parameters:

Parameter	Type	Required	Description
instID	str	Yes	The class name (must be one of the 26 registered classes)
parent	Inst or str	No	Parent instance or parent path
name	str	No	Instance name, defaults to instID
properties	table	No	Initial property values
Valid class names:

Part, SpawnLocation, Model, PointLight, RigJoint, Rig, Attachment, Camera, Folder, RemoteEvent, BindableEvent, Script, ScreenGui, Frame, ScrollFrame, TextLabel, TextButton, ImageLabel, ImageButton, TextBox, LocalScript, Player, Character, Team, Gear, Sound

12.2 Validation Behavior
Inst.new("Part") — works ("Part" is a registered class)

Inst.new("Plank") — error ("Plank" is not a registered class)

Inst.new(someFunc()) — works if someFunc() returns a valid class name at runtime

Inst.new(someVar) — works if someVar holds a valid class name at runtime

Inst.new(nil) — error (no class provided)

This means dynamic class names work:

| func CreateInstance(Type)
| return Inst.new(Type)
| end
|
| var wall = CreateInstance("Part")

12.3 Examples
Create a basic part:

| var part = Inst.new("Part")

Create with parent and name:

| var floor = Inst.new("Part", workspace, "Floor")

Create with full properties:

| var wall = Inst.new("Part", workspace, "Wall", {
| coordinates = Vec3.new(10, 5, 0),
| size = Vec3.new(1, 10, 20),
| color = [200, 200, 200],
| surfaceMaterial = "Brick",
| anchored = true,
| shape = "Box"
| })

12.4 Adding to the Scene
Passing a parent adds the instance to the scene immediately:

| var part = Inst.new("Part", workspace, "MyPart")

Alternatively, set .parent after creation:

| var part = Inst.new("Part", nil, "MyPart")
| part.parent = workspace

13. Instance Members
Every instance exposes the same member API, regardless of class. The class determines which properties are valid.

13.1 Common Fields
Member	Type	Description
.name	str	The instance's name
.parent	Inst or nil	The parent instance
.children	table	Child instances
.instID	str	The class name
13.2 Common Methods
Method	Description
:Destroy()	Removes the instance and all its children
:Clone()	Returns a deep copy of the instance
:FindFirstChild(name)	Searches direct children by name
:FindFirstDescendant(name)	Searches recursively by name
:IsA(instID)	Returns true if the instance is of the given class
13.3 Properties
Instance properties are accessed directly by name. Property names are the same as in .lw files — camelCase for main properties:

| floor.color = [255, 0, 0]
| floor.size = Vec3.new(10, 1, 10)
| floor.anchored = true

Subproperties (like Rig.Health, Rig.WalkSpeed) use PascalCase:

| rig.Health = 100
| rig.WalkSpeed = 20

13.4 Property Types
Setting a property to a value of the wrong type raises an error:

| floor.color = "red" -- error: color expects [R, G, B]

Setting a property that doesn't exist on the instance's class raises an error:

| floor.Health = 100 -- error: Part has no property 'Health'

13.5 Accessing Children
Direct child access uses dot notation:

| var door = workspace.House.Door

Iterating children:

| for i, child in ipairs(workspace.children) do
| output(child.name)
| end

14. Signals
Signals are LMLua's event system. Every event-bearing instance exposes the same signal API.

14.1 Signal Methods
Method	Meaning
:Connect(fn)	Subscribe a function to the signal
:Fire(...)	Fire the signal locally
:FireServer(...)	Fire to the server (RemoteEvent only)
:FireClient(player, ...)	Fire to one client (RemoteEvent only)
:FireClients(players, ...)	Fire to a table of clients (RemoteEvent only)
14.2 Connecting
:Connect takes a named function. Anonymous functions are not allowed.

| func onTicked(dt)
| output("tick: " .. dt)
| end
|
| Lib.StepService.Heartbeat:Connect(onTicked)

14.3 Built-in Signals
Signal	Instance / Service	Meaning
.Click	TextButton, ImageButton	Fires when the button is clicked
.FocusLost	TextBox	Fires when input focus is lost
.OnServerEvent	RemoteEvent	Fires on the server when a client fires
.OnClientEvent	RemoteEvent	Fires on the client when the server fires
.Heartbeat	Lib.StepService	Fires every frame
.Stepped	Lib.StepService	Fires every physics step
.KeyDown	Lib.InputService	Fires when a key is pressed
.KeyUp	Lib.InputService	Fires when a key is released
.MouseDown	Lib.InputService	Fires when a mouse button is pressed
.MouseUp	Lib.InputService	Fires when a mouse button is released
.PlayerAdded	Lib.Players	Fires when a player joins
.PlayerRemoved	Lib.Players	Fires when a player leaves
14.4 Firing a RemoteEvent
Client-side code fires to the server:

| func onButtonClicked()
| DamageEvent:FireServer(50)
| end
|
| startButton.Click:Connect(onButtonClicked)

Server-side code fires to one client:

| func onPlayerJoined(player)
| WelcomeEvent:FireClient(player, "Welcome!")
| end
|
| Lib.Players.PlayerAdded:Connect(onPlayerJoined)

Server-side code fires to multiple clients (table form):

| func onRoundStart(players)
| WelcomeEvent:FireClients(players, "Round started")
| end

The first argument is a table of Player instances. Remaining arguments are the event payload. Fires once per player in the table. An empty table fires to nobody without error.

| AlertEvent:FireClients({ player1, player2 }, "Hi")

Invalid entries raise an error:

| AlertEvent:FireClients({ player1, "notAPlayer" }, "Hi") -- error: entries must be Player instances

14.5 Receiving a RemoteEvent
On the server:

| func handleDamage(player, amount)
| var rig = player.Character.Rig
| rig:Damage(amount)
| end
|
| DamageEvent.OnServerEvent:Connect(handleDamage)

On the client:

| func handleWelcome(message)
| output(message)
| end
|
| WelcomeEvent.OnClientEvent:Connect(handleWelcome)

14.6 Disconnecting
:Connect returns a connection object with a :Disconnect() method:

| var conn = startButton.Click:Connect(onButtonClicked)
| conn:Disconnect()

15. Services & Lib
Services are engine-level systems — step callbacks, input, players, data. They are accessed through the Lib global.

15.1 The Lib Global
Lib exposes all services as properties:

| Lib.StepService
| Lib.InputService
| Lib.Players
| Lib.DataStore

15.2 Service List
Service	Purpose
Lib.Players	Players, join/leave events
Lib.LerpService	Interpolation
Lib.StepService	Frame/step callbacks
Lib.InputService	Keyboard/mouse/touch
Lib.DataStore	Data persistence (Supabase-backed)
There is no Lib.SoundService. Audio is handled entirely through Sound instances.

15.3 game:GetLib(ServiceName)
The same services can be accessed via a method call:

| var step = game:GetLib("StepService")
| step.Heartbeat:Connect(onTicked)

Both forms return the same service object. Lib.StepService is equivalent to game:GetLib("StepService").

15.4 Common Service Examples
StepService — run code every frame:

| func onHeartbeat(dt)
| -- runs every frame
| end
|
| Lib.StepService.Heartbeat:Connect(onHeartbeat)

InputService — react to a key press:

| func onKeyDown(key)
| if key == "E" then
| output("Interact!")
| end
| end
|
| Lib.InputService.KeyDown:Connect(onKeyDown)

Players — handle joins and leaves:

| func onPlayerAdded(player)
| output("Joined: " .. player.name)
| end
|
| func onPlayerRemoved(player)
| output("Left: " .. player.name)
| end
|
| Lib.Players.PlayerAdded:Connect(onPlayerAdded)
| Lib.Players.PlayerRemoved:Connect(onPlayerRemoved)

16. The game Global
game is the root access point for the scene tree and services.

16.1 Dotted Access
Instances are accessed directly through their container global:

| var floor = workspace.Floor
| var door = workspace.House.Door
| var mainGui = interface.MainGui

16.2 game:find(...)
game:find resolves an instance, taking either an instance reference or a string path. It always raises an error if the instance doesn't exist — it never returns nil.

Form 1 — validates an instance reference:

| var floor = game:find(workspace.Floor)

If workspace.Floor is nil, this raises an error.

Form 2 — searches by dotted path string:

| var floor = game:find("workspace.Floor")

Returns the instance, or raises an error if it doesn't exist.

16.3 Differences from Dotted Access
Expression	Behavior
workspace.Floor	Returns the instance, or nil
game:find(workspace.Floor)	Returns the instance, or errors
game:find("workspace.Floor")	Returns the instance, or errors
Use dotted access when the instance might not exist and you want to check. Use game:find when the instance must exist and you want an error if it doesn't.

17. World & Scene Access
17.1 Top-Level Containers
The following containers are implicit — they always exist as globals:

Global	Purpose
workspace	3D scene
replicated	Replicated storage
server	Server container

starter	Player template container
17.2 Sub-Containers
Global	Path

17.3 Adding to the Scene
When you create an instance and set its parent, it appears in the scene:

| var part = Inst.new("Part", workspace, "MyPart")

Reading it back:

| output(workspace.MyPart.name) -- "MyPart"

| var root = workspace
| for i, child in ipairs(root.children) do
| output(child.name .. " is a " .. child.instID)
| end

18. Rig and RigJoint Runtime
18.1 Rig
A Rig is a Humanoid-style controller attached to a Character or NPC model.

Properties:

Property	Type	Description
Health	number	Current health
MaxHealth	number	Maximum health
WalkSpeed	number	Movement speed
JumpPower	number	Jump strength
State	str	"Idle", "Walking", "Jumping", "Falling"
RootPart	str	Name of the root part
HeadPart	str	Name of the head part
TorsoPart	str	Name of the torso part
Methods:

Method	Description
rig:Damage(n)	Subtract n from Health
rig:Move(dir)	Move the rig in direction dir (a Vec3)
rig:Jump()	Apply a jump impulse
rig:Kill()	Set Health to 0 and enter the dead state
Example:

| func damageOnClick(player, amount)
| var rig = player.Character.Rig
| rig:Damage(amount)
| if rig.Health <= 0 then
| rig:Kill()
| end
| end

18.2 RigJoint
A RigJoint connects two parts and drives their relative transform.

Properties:

Property	Type	Description
coordinates	Vec3	The joint transform
part0	str	Name of the first joined part
part1	str	Name of the second joined part
Joints are driven automatically by the parent Rig. Scripts typically don't manipulate RigJoint directly unless building a custom skeleton.

18.3 Character and Player
player.Character returns the player's Character instance. character.Rig returns its Rig.

| func onPlayerAdded(player)
| player.Character.Rig.Health = 100
| end

19. Sound Runtime
A Sound is an audio source that can be parented to a part, model, or UI element.

19.1 Properties
Property	Type	Description
soundId	str	Asset path or URL
volume	number	Playback volume (0.0–1.0)
pitch	number	Playback pitch multiplier
loop	boolean	Whether the sound loops
playing	boolean	Whether the sound is currently playing
range	number	Audible distance (when is3D is true)
is3D	boolean	Whether the sound is positional
19.2 Methods
Method	Description
sound:Play()	Start playback
sound:Stop()	Stop playback and reset to the beginning
sound:Pause()	Pause playback, keeping the current position
sound:Resume()	Resume playback from the paused position
19.3 Example
| var footstep = Inst.new("Sound", workspace.Player1.LeftFoot, "Footstep", {
| soundId = "assets://sounds/step_grass.ogg",
| volume = 0.6,
| loop = false,
| is3D = true,
| range = 20
| })
|
| func playFootstep()
| footstep:Play()
| end
|
| Lib.StepService.Heartbeat:Connect(playFootstep)

20. DataStore Service
Lib.DataStore provides persistent storage for player data, world state, and global values. It is backed by Supabase (Postgres), but scripts never touch HTTP directly — the API is high-level.

20.1 Methods
Method	Description
Lib.DataStore:GetAsync(key)	Returns the value stored at key, or nil
Lib.DataStore:SetAsync(key, value)	Stores value at key
Lib.DataStore:UpdateAsync(key, func)	Atomically updates the value at key
Lib.DataStore:RemoveAsync(key)	Deletes the value at key
20.2 Keys
Keys are strings. Common patterns:

Key	Purpose
"player_" .. player.userId	Per-player save data
"leaderboard_global"	Global leaderboard
"world_state"	World-wide state
20.3 Example — Load Player Data
| func onPlayerAdded(player)
| var key = "player_" .. player.userId
| var data = Lib.DataStore:GetAsync(key)
| if data == nil then
| data = { Coins = 0, Level = 1 }
| Lib.DataStore:SetAsync(key, data)
| end
| player.Data = data
| end
|
| Lib.Players.PlayerAdded:Connect(onPlayerAdded)

20.4 Example — Save Player Data
| func onPlayerRemoved(player)
| var key = "player_" .. player.userId
| Lib.DataStore:SetAsync(key, player.Data)
| end
|
| Lib.Players.PlayerRemoved:Connect(onPlayerRemoved)

20.5 Atomic Updates
UpdateAsync runs a function that receives the current value and returns the new value:

| func addCoins(old)
| if old == nil then
| old = { Coins = 0, Level = 1 }
| end
| old.Coins = old.Coins + 10
| return old
| end
|
| Lib.DataStore:UpdateAsync("player_12345", addCoins)

21. Compilation Model
LMLua is a source-to-source transpiler. Its pipeline is:

Lexer — tokenizes the .lmlua source.

Rewriter — handles var / const / global / cglobal, server / client / func, and output → print. Also enforces const and cglobal assignment guards.

Lua source — emits valid Lua.

Lua runtime — executes on Lua 5.1, 5.2, 5.3, 5.4, or LuaJIT.

21.1 Rewrite Rules
LMLua	Lua
var x = 1	local x = 1
const X = 1	local X = 1 with compile-time guard
global x = 1	x = 1
cglobal X = 1	X = 1 with program-wide compile-time guard
server function f()	function f()
client function f()	function f()
func f()	function f()
output(...)	print(...)
The four built-in types (Vec2, Vec3, Dim, Inst), the Lib global, the game global, and the top-level containers (workspace, replicated, server, interface, starter) are not rewritten. They are provided as runtime globals loaded before user code runs.

21.2 Runtime Preload
The LMLua runtime injects the following as globals before user code executes:

Vec2, Vec3, Dim, Inst — constructors

game — scene tree accessor

Lib — service library

workspace, replicated, server, interface, starter — top-level containers

21.3 Compile-Time Errors
Error	Trigger
cannot assign to const 'NAME'	Reassignment of a const binding
cannot assign to cglobal 'NAME'	Reassignment of a cglobal binding
expected identifier after 'var'	Missing name
expected identifier after 'const'	Missing name
expected identifier after 'global'	Missing name
expected identifier after 'cglobal'	Missing name
expected 'function' after 'server'	Missing function
expected 'function' after 'client'	Missing function
expected 'function' after 'func'	Missing function
21.4 Runtime Errors
Error	Trigger
Inst.new: "X" is not a registered instance class	Invalid instID
game:find: instance not found at path "X"	Missing instance
<class> has no property 'X'	Unknown property
property 'X' expects <type>	Type mismatch
signal :Connect expects a function	Bad signal argument
:FireClients entries must be Player instances	Invalid client table entry
22. Complete Example
A small world with a Part, a Sound, a button that fires a RemoteEvent to the server, and a Rig that takes damage.

22.1 The .lw File
| {
| | "format": "lime-world",
| | "version": "1.1",
| | "instances": [
| | | {
| | | | "instID": "Part",
| | | | "name": "Floor",
| | | | "parent": "workspace",
| | | | "properties": {
| | | | | "coordinates": [0, 0, 0],
| | | | | "size": [50, 1, 50],
| | | | | "color": [80, 80, 80],
| | | | | "surfaceMaterial": "Concrete",
| | | | | "anchored": true,
| | | | | "shape": "Box"
| | | | }
| | | },
| | | {
| | | | "instID": "TextButton",
| | | | "name": "DamageButton",
| | | | "parent": "interface",

23. Grammar Reference (EBNF)
A program is a sequence of statements.

text
program = { statement }

statement = varDecl
          | constDecl
          | globalDecl
          | cglobalDecl
          | functionDecl
          | ifStmt
          | whileStmt
          | repeatStmt
          | forStmt
          | doStmt
          | returnStmt
          | breakStmt
          | exprStmt

varDecl      = "var" Name "=" expr
constDecl    = "const" Name "=" expr
globalDecl   = "global" Name "=" expr
cglobalDecl  = "cglobal" Name "=" expr

functionDecl = funcQualifier "function" funcName funcBody
funcQualifier = "server" | "client" | "func"
funcName     = Name { "." Name } [ ":" Name ]
funcBody     = "(" [ paramList ] ")" block "end"

ifStmt     = "if" expr "then" block
             { "elseif" expr "then" block }
             [ "else" block ]
             "end"

whileStmt  = "while" expr "do" block "end"

repeatStmt = "repeat" block "until" expr

forStmt    = numericFor | genericFor
numericFor = "for" Name "=" expr "," expr [ "," expr ] "do" block "end"
genericFor = "for" namelist "in" explist "do" block "end"

doStmt     = "do" block "end"
returnStmt = "return" [ explist ]
breakStmt  = "break"
exprStmt   = expr

block = { statement }
Expressions follow Lua's precedence levels: comparison, concatenation, additive, multiplicative, unary, power, primary.

24. Differences from Lua
Feature	Lua	LMLua
Local variable	local x = 1	var x = 1
Immutable local	none	const X = 1
Global variable	x = 1	global x = 1
Immutable global	none	cglobal X = 1
Function	function f() end	server function f() end, client function f() end, or func f() end
Print	print(...)	output(...)
Anonymous functions	function(x) ... end	not supported
Vector 3D	user library	Vec3.new(x, y, z)
Vector 2D	user library	Vec2.new(x, z)
Dimensions	user library	Dim.New(w, h)
Instance	user library	Inst.new(instID, ...)
Services	user library	Lib.ServiceName
Scene access	user library	game, workspace, etc.
All other syntax	—	identical
25. Differences from C++
Feature	C++	LMLua
Function storage class	static, inline, virtual	server, client, func
Immutability (local)	const T x = ...	const X = ...
Immutability (global)	const T x = ... at namespace scope	cglobal X = ...
Type annotations	int x = 5	not required
Block delimiters	{ ... }	do ... end or then ... end
Statement terminator	;	newline
Vector types	std::array, glm::vec3	Vec3, Vec2
Namespaces	namespace N { ... }	planned
Classes	class C { ... }	planned — use metatables
Exceptions	try / catch	planned — use pcall
Services	static singletons	Lib.ServiceName

and, break, cglobal, client, const, do, else, elseif, end, false, for, func, function, global, if, in, nil, not, or, repeat, return, server, then, true, until, var, while.
